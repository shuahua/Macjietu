## 方案选择与实施边界

1. **已采用：保存经验证的接缝计划，增量维护两端。** 保留原有匹配器和保守阈值；每个会话持有有序帧及相邻边的 shift/seam，新扩展帧仅匹配两个边界以验证方向和歧义，不重新验证历史边。回滚识别仍须把新帧与覆盖区间端点比较，但读取已保存跨度，不重算该区间历史边；预览、完成和错误恢复复用计划。计划随会话快照传入后台任务，成功后按 session 身份更新，取消或迟到结果不能污染新会话。不建立跨会话无界全局缓存。
   - 渲染继续使用有界缩略图及完成时一次全尺寸输出，明确它仍遍历历史裁剪片段，不称为完全增量像素渲染。先消除重复配准而不是大规模改写存储层。
   - 固定头尾沿用当前接缝规则；重复帧不贡献像素，新的接缝修改最后一个真正有内容的片段。上插、下插都必须保持一致约束。
   - 保留已有背压和自动未确认暂停。本阶段不追加依赖完全静止的多帧门槛，避免把动态页面永久卡住；也不把三帧相同当成到底。
2. **相位相关或归一化模板匹配替换当前匹配器。** 方法成熟，但不能直接解决已证实的历史重匹配问题，还会新增集成成本及不同误判面；目前不推荐引入 OpenCV 重依赖或改写匹配阈值。
3. **磁盘分块/只保存新增条带/分层缩略图。** 更彻底降低完整帧持有与历史绘制成本，但双向扩展、回滚、固定头尾、取消清理和内存预算需要更大改动。留作后续，不在没有数据的情况下盲目实现。

### 实现顺序与验收

实际按服务计划类型与共享渲染 → 协调器全链路接入 → 回归和同输入基准 → 全量检查顺序实施。生产接入覆盖预览、完成和失败恢复，而非只添加无人调用的缓存 API。新增测试验证上/下扩展、回滚、重复帧、固定头尾的逐像素正确性，以及异常尺寸、不相关帧被拒后计划不变。既有测试继续验证歧义拒绝、取消重启不串会话和失败恢复。用确定性匹配调用计数证明预览/导出不增加历史配准次数；以同一合成多帧输入分别运行原路径与计划路径，记录耗时和输出像素相等性。全量 swift test 及 git diff --check 均通过。
